# Nablon — обязательный контроль принятых решений

**Статус:** проект механизма контроля; до сверки с утверждёнными первоисточниками нельзя считать этот документ полным реестром решений.

## Правило для любого изменения пользовательского сценария

Перед созданием или изменением сцены исполнитель обязан:
1. Найти действующие утверждённые требования к цели, языку, формату ввода, подсказкам, последовательности сложности, наблюдаемым действиям и измерению результата.
2. Указать в PR ссылки на источники этих требований и конкретные изменения, которые им соответствуют.
3. Приложить дословный текст всех новых или изменённых экранов, ответы мира на действия и доступные подсказки.
4. Выполнить автоматические проверки и отдельную редакционную проверку. Отсутствие подтверждения = проверка не пройдена, а не «требований нет».
5. Если новая идея противоречит принятому решению, остановить работу и запросить отдельное решение владельца. Не менять действующее решение молча.

## Минимальные проверяемые вопросы

- Язык понятен без специальной подготовки? Нет канцелярита, нерасшифрованных технических слов и лишних инструкций?
- Сложность — в выборе действия, а не в расшифровке текста?
- Может ли человек выразить собственное действие, а не только угадывать предложенный ответ?
- Подсказки не подменяют самостоятельный выбор? Есть ли доступный выход при затруднении?
- Различаются ли наблюдаемые действия и интерпретация их причин?
- Не считается ли один удачный исход доказательством обучающего эффекта?
- Сценарий соответствует утверждённому протоколу эксперимента или явно отделён от него?

## Ограничения

Этот файл сам по себе **не блокирует** объединение PR. Для технической блокировки нужны CI-проверки и настройка GitHub branch protection / rulesets с обязательным статусом проверки. Даже тогда редакционная оценка требует человека. Не выдавать чек-лист за доказательство качества.
