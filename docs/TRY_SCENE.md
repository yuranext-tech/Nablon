# `/try`: короткая интерактивная сцена

`/try` — отдельный от ежедневного числового прогноза мини-эпизод. Он не читает
и не пишет PostgreSQL, `users`, `observations`, `PROBES` или cron-состояние.
Это не оценка человека и не психологический диагноз.

## Что видит пользователь

В сцене доступны четыре inline-кнопки: «Повторить действие», «Изменить
способ», «Узнать результат» и «Завершить». Первый запуск для пользователя
даёт ситуацию, где повторение даёт конкретный прогресс; следующий запуск —
ситуацию, где повторение не даёт новых данных, а смена способа даёт конкретный
прогресс. Дальше ситуации чередуются. Максимум — четыре действия.

Callback содержит одноразовый токен сцены и её текущий ход. Старые кнопки,
повторная доставка callback и попытка другого пользователя нажать кнопку не
изменяют состояние. Новый `/try` завершает предыдущую сцену этого пользователя.

## Данные и рестарт

Сессии хранятся только в памяти. После рестарта процесса активная сцена и её
кнопки становятся устаревшими; пользователь получает понятное сообщение и
может запустить `/try` снова. В памяти остаётся ограниченный журнал только
принятых `repeat`/`change` событий: ситуация, действие и наблюдаемый результат
`progress`/`no_progress`. Он не содержит Telegram ID, имени, текста или
интерпретации поведения.

## Безопасность

Публичный `/debug` удалён: health server возвращает для него `404` и никогда
не читает пользовательские записи. Если прежний секрет бота когда-либо мог
оказаться в URL, истории браузера, прокси или логах, его необходимо перевыпустить
в используемом менеджере секретов до следующего деплоя. Сам деплой и изменение
секретов этой задачей не выполняются.

## Метрика эксперимента

Для сопоставления с будущей задачей без DC-005E фиксируются: ручные операции
владельца, время от Issue до независимо проверенного PR и количество циклов
исправлений. Автоматически эти показатели не интерпретируются и не отправляются
в Telegram; до независимой проверки последний показатель не считается нулевым.
