# Ознакомление 01 — Последняя копия

Сцена согласована владельцем в рабочем обсуждении. Она проверяет управление интерфейсом. Первый экран без таймера и дальнейшие тексты находятся в `orientation/episode.js`.

- «Открыть папку» показывает два файла без дополнительной инструкции.
- Любой из двух файлов, выбранный с экрана списка без запроса помощи, подтверждает прохождение последовательности. Достижение цели отмечается отдельно при открытии файла от 14 ноября.
- «Завершить» доступно на каждом активном экране и фиксирует остановку. При отсутствии второго содержательного действия понимание остаётся непроверенным.
- Команда `/help` в активном эпизоде готовит нейтральную инструкцию. Первый содержательный ход после запроса помечается как выполненный с помощью даже при неопределённой доставке. После этого следующий выбор файла без новой подсказки может подтвердить понимание управления. Ранее записанные запросы помощи и отметки о ходах сохраняются. Старая кнопка после сбоя показа помощи возвращает актуальный экран с подсказкой и актуальными кнопками. Ход применяется только после нажатия актуальной кнопки. Каждый новый запрос помощи записывается один раз. Повтор той же доставки Telegram заново показывает актуальный экран и не добавляет запрос.
- Возврат через `/try` показывает текущий экран, а после завершения — последний итог. Для нового прохождения после завершения используется `/try_again`. При активном эпизоде эта команда показывает текущий экран.

## Изолированный запуск

Используется существующая точка входа `npm start` с `NABLON_RUNTIME_MODE=try-only` и `NABLON_TRY_EPISODE=last-copy-v1`. Для согласованного пилота нужны отдельная PostgreSQL с применённым `orientation/schema.sql`, её URL в `NABLON_ORIENTATION_DATABASE_URL`, стабильный секрет псевдонимизации `NABLON_ORIENTATION_SUBJECT_KEY` и настроенный токен бота. Смена секрета меняет псевдонимы и разрывает связь с прежними эпизодами. Хранилище не использует таблицы числового цикла.

Состояние, события с порядком внутри эпизода и полный receipt сохраняются одной транзакцией. Повтор проверяется до версии эпизода. Первичные события содержат текст подготовленного последствия и версию предыдущего экрана, из которого пришла кнопка. Подготовленное последствие, успешный ответ Telegram API и действие с кнопки соответствующего экрана хранятся раздельно. Подтверждение API сохраняется в `nablon_orientation_telegram_sends` после успешного редактирования или резервного ответа и не означает прочтения. Если Telegram принял операцию, а приложение завершилось до записи подтверждения, запись об отправке может отсутствовать. Повтор доставки может показать экран ещё раз, но не применяет ход повторно. Если сообщение потеряно, пользователь может открыть `/try` или повторно нажать кнопку. Восстановление выполняется по запросу пользователя, фоновой доставки здесь нет.

## Проверки

`npm test` выполняет модульные проверки и прежние тесты. Чтобы выполнить интеграционный набор, перед запуском укажите `NABLON_ORIENTATION_TEST_DATABASE_URL` с адресом отдельной одноразовой PostgreSQL. Тесты применяют схему и записывают синтетические эпизоды. Транспорт Telegram подменён. Для существующей изолированной базы повторно примените `orientation/schema.sql`: добавится отдельная таблица подтверждений отправки.

Управление понятно реальным участникам только после наблюдаемого прохождения. До такого прохождения отдельно согласовать доступ к базе пилота и срок хранения записей.
