# Обязательный процедурный контроль Nablon + Becoming

**Статус: принято владельцем 2026-11-08.** Применяется к обоим проектам. GitHub Rulesets на текущем тарифе приватных репозиториев не обеспечивают принудительную блокировку: это организационный стандарт, а не обещание технической защиты.

## Источники истины
1. Утверждённая архитектура Becoming v1.0 от 2026-11-02: https://github.com/yuranext-tech/becoming/blob/main/docs/architecture/Becoming_Architecture_v1.0_APPROVED_2026-11-02.md
2. Для Nablon — утверждённые продуктовые решения и полные исходные тексты сценариев с версиями. Черновик адаптивного набора от 2026-10-31 не объявлять утверждённым без отдельного решения владельца.
3. Если первоисточник недоступен, фиксировать «не проверено», а не предполагать соответствие.

## Перед существенным изменением
Существенные изменения: сценарий, пользовательский язык, свободный ввод/кнопки, подсказки, сложность, измерение, интерпретация поведения, прогноз, персонализированная помощь, интерфейс между Nablon и Becoming.
- Найти действующий утверждённый источник и его версию; указать ссылку в PR.
- Сверить полный пользовательский текст, действия, последствия, подсказки и измерения; сохранить редакционный эталон без пересказа.
- Разделять наблюдение, гипотезу, прогноз и доказанную пользу помощи. Не делать вывод о человеке из одного исхода.
- Указать выполненные тесты и независимую проверку, не выдавать декларации за запуск.
- При противоречии остановить изменение: **«Ожидает решения владельца»**. Без нового решения не переписывать прежнее.
- До сверки не объединять изменение в main и не выкатывать на Render. Проверка CI — необходимый технический сигнал, но не доказательство продуктового качества.

## Регулярные проверки
- **Раз в 3 дня:** проверка только восьми ключевых принципов, важных сценариев и связки Nablon–Becoming; сверка фактических изменений GitHub/Render с первоисточниками. Результат: соблюдено / нарушение / не проверено, конкретные SHA и до трёх действий.
- **Раз в месяц:** расширенный технический аудит реализации, сохранения данных, безопасности, интеграции и тестов.
- После первого месяца оценить, сколько существенных изменений проверено, какие отклонения обнаружены и какие ранее принятые решения были потеряны.

## Ключевые продуктовые принципы
1. Самостоятельный выбор способа и наблюдаемые последствия, не угадывание кнопок.
2. Простой, понятный человеческий язык.
3. Интересные жизненные сценарии и сохранение удачной формы подачи.
4. От простого к сложному, без скрытых правил для новичка.
5. Помощь без подмены самостоятельного действия.
6. Один исход не доказывает обучающий эффект или характеристику личности.
7. Не отменять принятые решения и замороженные протоколы молча.
8. Becoming — самостоятельный поведенческий мотор; Nablon — тренировочный интерфейс. Сырые наблюдения, гипотезы, прогнозы и эффективность вмешательств разделены.

## Статусы
**Принято / Ожидает решения владельца / Ожидает внешнего подтверждения / PARK.**

## Ограничения
Этот стандарт не заменяет независимую редакционную оценку, не гарантирует автоматическую блокировку PR и не подтверждает, что все старые сценарии уже перенесены в GitHub. Отсутствие проверки — открытый риск, не успех.
