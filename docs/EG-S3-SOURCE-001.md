# EG-S3-SOURCE-001 — технический адаптер источника S3

**Статус:** черновой изолированный инженерный PR, **не** допуск рабочего S3.
**Основание:** явное разрешение владельца; контроль EG-INTEGRATION-P1-001 принят отдельно.
**База:** `audit/nablon-adaptive-v01-delivery-fix` на `8570a5f1dcea920a7c1142413690fca8fe1f32bd`.

## Объём

`adaptive/s3-source.js` добавляет журнал фактов вокруг существующего `adaptive/engine.js` **без изменения самого движка**. Исходный движок остаётся идентичным Git blob `74b19548a67cafbd96aa02c5d4d93baed66a80e5`. Тексты, порядок сцен, набор действий, последствия, подсказки, переходы S4A/S4B, результаты и лимиты не меняются. Существующий контракт симуляции сохраняется.

Журнал получает `episodeId` (UUID), `sceneId=S3`, `sceneVersion=adaptive-set-v0.1`, `eventId` (`episodeId:sequence`), уникальную последовательность, `commandId` от вызывающего транспорта и время записи. `ACTION_ACCEPTED` и `CONSEQUENCE_PREPARED` записываются отдельно, но относятся к одной команде. Повтор с тем же ID и содержимым возвращает результат без нового хода, изменение содержания с тем же ID даёт `CONFLICT`. Отдельно фиксируются запрос помощи и *заявленное* предъявление.

**Предупреждение:** `PRESENTATION_REPORTED` — не доказательство реального предъявления. Даже `deliveryClaim=confirmed` означает только вызов `engine.presentation()` в автономной симуляции. Не превращать этот факт в доверенное свидетельство `exposure` или `help`. При отсутствии независимого наблюдателя принимающий модуль должен вернуть `EXPOSURE_UNKNOWN` и `independence=unknown`.

## Как использовать в прототипе

1. Через существующий движок дойти до нового S3, не совершая ни одного действия S3.
2. Вызвать `createSource(engineState)` **один раз** для этого эпизода и сохранить весь объект журнала.
3. Выполнять все команды S3 через `apply(journal, {commandId, kind, ...})`: `presentation` (`presentationKind`, `delivery`, `turn`), `action` (`action`), `help`. Вызывающий транспорт обязан обеспечить неизменяемый уникальный ID команды.
4. После каждой успешно применённой команды атомарно сохранить **весь** объект (движок, события, квитанции). В автономной демонстрации это сериализуемый JSON; реально надёжная запись и транзакционная обработка доставки ещё не реализованы.
5. `intakePacket(journal, consequenceId, nextActionId)` формирует пакет для уже принятого `intake.mjs`. **Первичные записи для `readPrimaryEvents` должны читаться независимо от входящего пакета, из доверенного хранилища.** Передача клиентом того же JSON не доказывает подлинность.

```bash
node --test --test-reporter=tap adaptive/s3-source.test.js
# Для реальной проверки границы укажите путь к неизменённому файлу из принятого EG-INTEGRATION-P1-001:
EG_INTAKE_PATH=/path/to/EG-INTEGRATION-P1-001/intake.mjs node --test --test-reporter=tap adaptive/s3-source.intake.test.mjs
```

В Windows PowerShell:

```powershell
$env:EG_INTAKE_PATH = 'C:\path\to\EG-INTEGRATION-P1-001\intake.mjs'
node --test --test-reporter=tap adaptive/s3-source.intake.test.mjs
```

Тесты не требуют PostgreSQL: они проверяют структуру первичных событий, поведение исходного движка, идемпотентность и совместимость с уже принятым принимающим модулем при синтетических наблюдениях. Они **не** проверяют реальную запись через Telegram/PostgreSQL или реальные свидетельства предъявления.

## Нерешённые границы и критерии перед закрытием четырёх P1 рабочего S3

- Подключить адаптер ко **всем** фактическим входам S3: прямые вызовы старого движка обходят журнал. Действующий S3 пока вообще не является Telegram-маршрутом.
- Гарантировать атомарность записи состояния, истории и квитанций в доверенное хранилище, с независимым чтением первичных записей и проверкой повторов после перезапуска.
- Подключить реальное происхождение ответов Telegram отдельно от подготовки результата, а при отсутствии подтверждения чтения сохранить `EXPOSURE_UNKNOWN`.
- Проверить, что записи внешнего источника о помощи и времени наблюдения имеют проверенные полномочия и сопоставимые часы; взаимоисключающие записи не уничтожаются.
- Выполнить сквозные PostgreSQL-тесты на настоящем маршруте S3 и независимую проверку. Нельзя выдавать этот прототип за закрытие четырёх P1 рабочего S3 или за разрешение персонализации.
- P2 незавершённого эпизода отдельно ожидает решения владельца. Никаких решений в рамках этого PR.

**Стоп-правило:** не создавать новую БД, сервис или механизм интерпретации только ради `EG-S3-SOURCE-001`. Если станет необходима существенная переделка автономного движка или игрового сценария, остановиться и запросить новое решение владельца с обоснованием. Рабочие Becoming и Render не затрагивать.
